# מערכת הנהלת חשבונות חכמה (שם עבודה)

מערכת לניהול הכנסות, הוצאות, מע"מ ומועדי דיווח לכל סוגי העסקים בישראל:
עוסק פטור, עוסק מורשה, חברה בע"מ, שותפות ועמותה.

> ⚠️ **שלב פיתוח.** הכללים המקצועיים (שיעורים, ספים, מועדים) הם ברירות מחדל
> שיש לאמת מול רשות המסים / איש מקצוע לפני שימוש בדיווח אמיתי.

## מה יש כרגע

- **התחברות משתמשים**: הרשמה, התחברות והתנתקות.
  - סיסמאות מוצפנות ב־scrypt, וסשנים נשמרים בשרת (בעוגייה רק טוקן אקראי, ב־DB רק ה־hash שלו).
  - נעילה ל־15 דקות אחרי 5 ניסיונות כושלים, והודעת שגיאה אחידה שלא חושפת אילו כתובות רשומות.
- **הרשאות לפי עסק**: בעלים (הכול), רואה חשבון (מסמכים והוצאות), צפייה בלבד.
  כל דף ופעולה בודקים חברות ותפקיד בשרת (`src/lib/auth/dal.ts`).
- **הקמת עסק** לפי סוג, עם בדיקת ספרת ביקורת למספר עוסק / ח.פ.
- **הפקת מסמכים**: חשבונית מס, חשבונית מס קבלה, קבלה, זיכוי, חשבון עסקה, קבלה על תרומה.
  - כל עסק מקבל רק את סוגי המסמכים שמותרים לו.
  - מספור רץ לכל סוג מסמך, ללא קפיצות, וללא אפשרות להפיק בתאריך מוקדם מהמסמך האחרון.
  - סימון אוטומטי של מסמכים שדורשים **מספר הקצאה** (חשבוניות ישראל).
- **חשבוניות פתוחות**: מעקב אחרי חשבוניות מס וחשבונות עסקה שלא שולמו (פתוח / באיחור מעל 30 יום),
  סכום פתוח בלוח הבקרה, והפקת קבלה על חשבונית בלחיצה (או חשבונית מס קבלה על חשבון עסקה).
  חשבונית מסומנת כשולמה מקבלה, מהתאמה לתנועת בנק או בסימון ידני — וביטול ההתאמה מחזיר אותה לפתוחה.
- **לקוחות**: רשימת לקוחות עם סך החיובים, דף לקוח עם כל המסמכים שלו, ובחירת לקוח שמור בהפקת מסמך
  (או שמירת לקוח חדש באותה פעולה). עריכת לקוח לא משנה מסמכים שכבר הופקו.
- **PDF לכל מסמך**: עברית מלאה, כל הפרטים שחשבונית מס צריכה, וסימון "מקור" בהפקה הראשונה
  ו"העתק נאמן למקור" בכל הפקה אחריה (הסימון אטומי ונרשם ביומן הפעולות).
- **שליחת מסמכים במייל** ללקוח עם PDF מצורף, ויומן של כל מייל שנשלח. **איפוס סיסמה** דרך קישור במייל
  (בתוקף לשעה, עד 3 בקשות בשעה, מנתק את כל המכשירים). בלי ספק מיילים מוגדר — המיילים נרשמים ביומן בלבד.
- **קבלות**: העלאת תמונה או PDF של כל קבלה ושמירתה עם ההוצאה (סוג הקובץ נבדק לפי התוכן).
  כשמוגדר `ANTHROPIC_API_KEY`, ‏Claude קורא את הקבלה וממלא ספק, מספר עוסק, תאריך, סכום, מע"מ, מספר חשבונית
  וקטגוריה; המערכת בודקת את הערכים (ספרת ביקורת, תאריך, סבירות המע"מ, מטבע) ומציגה אזהרות לבדיקה לפני שמירה.
- **זיכרון ספקים**: המערכת לומדת מההוצאות הקודמות — הקלדת שם ספק מוכר ממלאת קטגוריה ומספר עוסק,
  וגם רישום הוצאה מתנועת בנק או מקבלה סרוקה משתמש בהיסטוריה (גם כשהשם כתוב אחרת, למשל "פז חברת נפט").
- **רישום הוצאות** עם חישוב מע"מ אוטומטי ו־15 קטגוריות עם שיעורי הכרה (למשל רכב: 45% מס, 2/3 מע"מ).
- **ייבוא תנועות בנק** מקובץ CSV שיוצא מאתר הבנק (כולל קידוד Windows-1255 ושורות פתיחה/סיכום),
  זיהוי כפילויות בייבוא חוזר, והצעות התאמה אוטומטיות: זיכוי ← חשבונית/קבלה, חיוב ← הוצאה.
  מתנועה שלא הותאמה אפשר לרשום הוצאה בלחיצה (הפרטים מתמלאים מהתנועה).
- **דוח מע"מ** לכל תקופה (חודשי / דו־חודשי), מוכן להזנה בדיווח המקוון.
- **דוח שנתי**: פילוח חודשי (הכנסות, הוצאות מוכרות, רווח, מע"מ), הוצאות לפי קטגוריה,
  וייצוא לאקסל לרואה החשבון: סיכום שנתי, כל המסמכים וכל ההוצאות.
- **לוח בקרה**: הכנסות, הוצאות מוכרות, רווח, מע"מ לתשלום, ומעקב תקרת עוסק פטור.
- **לוח מועדים**: מע"מ, מקדמות מס הכנסה, ביטוח לאומי ודוח שנתי, לפי סוג העסק.
- **יומן פעולות (audit log)** לכל פעולה.
- **ריבוי עסקים**: כל הנתונים מופרדים לפי עסק, ומשתמש אחד יכול לנהל כמה עסקים.

## מודול ביקורת דוחות (למשרדי רואי חשבון)

כלי עבודה לביקורת חיצונית: המערכת מבצעת את הבדיקות ומכינה את החומר, ושיקול הדעת וחוות הדעת נשארים אצל
רואה החשבון המבקר (רק רואה חשבון מוסמך ובלתי תלוי רשאי לחתום).

- **תיק ביקורת** לכל לקוח ושנה, בתוך המשרד, עם הפרדה מלאה בין משרדים.
- **קליטת ספרי הלקוח מקובץ במבנה אחיד** (BKMVDATA.TXT + INI.TXT, לפי הוראות רשות המסים 1.31) — מכל תוכנה רשומה,
  כולל זיהוי קידוד (Windows / DOS) ובדיקות שלמות לקובץ עצמו: מספור רשומות, רשומת סגירה, התאמה לסיכומי INI,
  התאמה בין אינדקס החשבונות לתנועות, ומספר עוסק שונה מהלקוח בתיק. אפשר גם כרטסת CSV.
- **מאזן בוחן** ואיתור פקודות לא מאוזנות.
- **סקירה אנליטית**: קליטת השנה הקודמת לאותו תיק, השוואת יתרות לפי חשבון או לפי קבוצה במאזן הבוחן, וסימון
  שינויים שגם מעל המהותיות לביצוע וגם מעל 10%, חשבונות חדשים / שנסגרו, וחודשים חריגים (מעל 2 סטיות תקן).
  לכל ממצא — הסבר מתועד עם שם הכותב והתאריך, ומונה "הוסברו". אזהרה כשנקלט קובץ של שנה אחרת.
- **התאמת בנק**: דף בנק (CSV) מול חשבון הבנק בספרים — התאמה לפי סכום ותאריך, פריטים שבספרים ועוד לא בבנק
  (כולל צ'קים שנפרעו אחרי סוף השנה, כראיה), תנועות בבנק שלא נרשמו, והפרש לא מוסבר; יתרה לפי אישור בנק.
- **סבירות מע"מ עסקאות**: לכל חודש — הכנסות × שיעור המע"מ באותו חודש מול המע"מ שנרשם, עם הצעה אוטומטית של
  החשבונות לפי השמות וסימון פערים מעל הסף הזניח.
- **בדיקת פקודות יומן**: שבת, סכום עגול, סמוך לסוף השנה / אחריו, בלי תיאור, מעל המהותיות, כפולות.
- **חוק בנפורד** (ספרה ראשונה, ספי Nigrini).
- **מהותיות** כוללת / לביצוע / זניחה.
- **מדגם כספי (MUS)** שניתן לשחזור לפי seed, וכל דגימה מחדש נרשמת ביומן.
- **ביקורת שכר (קובץ 126)**: קליטת הדיווח השנתי לרשות המסים לפי המפרט הרשמי (רשומות 10/20/30/40/50, 966 תווים),
  עם בדיקות השלמות המובנות בקובץ (צבירות רשומות העובדים מול רשומות הסיכום, והתאמה 126 ↔ 12 דיווחי 102).
  ממצאים על נתוני השכר: ת.ז. לא תקינה או כפולה, שכר ללא ניכויים, עובד ותיק ללא פנסיה, תשלום לעובד שעזב, תאריכים
  לא עקביים, שכר חריג, חודשים חריגים וקפיצות במספר העובדים. **התאמה שכר ↔ ספרים**: ברוטו, ב"ל מעביד, הפרשות
  סוציאליות, מס הכנסה ניכויים וב"ל לשלם מול חשבונות הספרים (מיפוי אוטומטי לפי שמות + תיקון ידני), כולל יתרות
  31.12 מול החוב הצפוי של דצמבר. לכל ממצא — תיעוד הסבר. נבדק עד כה רק על קבצים שנבנו לפי המפרט.

## ארכיטקטורה

```
src/
  lib/domain/     ← הלב: כללים וחישובים טהורים (מע"מ, מסמכים, דוחות, מועדים). בלי DB, עם בדיקות.
  lib/services/   ← שכבת נתונים: כל פונקציה מקבלת מזהה עסק ואוכפת הפרדה בין עסקים.
  db/             ← סכמת Postgres (Drizzle ORM). סכומים נשמרים באגורות כמספר שלם.
  app/            ← ממשק (Next.js, עברית RTL) ו־Server Actions עם ולידציה (Zod).
drizzle/          ← מיגרציות
```

בפיתוח מקומי ה־DB הוא PGlite: Postgres מלא שרץ בתוך התהליך, בלי להתקין שרת.
בייצור נחליף ל־Postgres מנוהל בלי לשנות את הסכמה.

## הרצה

הגדרות סביבה: העתיקו את `.env.example` ל־`.env.local` ומלאו לפי הצורך. שום הגדרה אינה חובה לפיתוח מקומי.

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # בדיקות
npm run typecheck
npm run lint
```

### הפקת PDF

ה־PDF מופק עם Chromium (דרך `playwright-core`), כי זו הדרך האמינה לעברית ולמספרים בתוך טקסט מימין לשמאל.
הגופן (Heebo, רישיון OFL) מוטמע מתוך `assets/fonts`, כך שאין תלות בגופנים של השרת.
בשרת ייצור יש להתקין Chromium ולהגדיר את משתנה הסביבה `CHROMIUM_PATH` לנתיב שלו.

שינוי בסכמה: עורכים את `src/db/schema.ts` ומריצים `npm run db:generate` (יוצר מיגרציה ומעתיק אותה גם
לפורמט של Netlify ב־`netlify/database/migrations`).

### העלאה ל־Netlify

- מסד הנתונים: Netlify Database (Postgres) — נוצר אוטומטית; המיגרציות מורצות בכל העלאה.
  משתנה סביבה: `DATABASE_DRIVER=netlify`. (לכל Postgres אחר: `DATABASE_URL`.)
- מגבלות בשרת serverless: אין Chromium — הפקת PDF ושליחת מסמכים במייל מחזירות הודעה שהפעולה אינה זמינה;
  גודל בקשה מוגבל ל־6MB.

## מפת דרכים

1. **השלמות להתחברות**: אימות אימייל, הזמנת משתמש שעדיין לא רשום במייל, אימות דו־שלבי.
2. **חיבור שירות מיילים אמיתי**: פתיחת חשבון Resend, אימות הדומיין והגדרת `RESEND_API_KEY` ו־`EMAIL_FROM`.
3. **חיבור לספק חשבוניות מאושר / API של רשות המסים** לקבלת מספרי הקצאה.
4. **אחסון קבצים ייעודי** לקבלות (כרגע נשמרות במסד הנתונים) ומסך ייעודי לצילום מהטלפון.
5. **ייבוא קבצי Excel מהבנק** (כרגע CSV בלבד).
6. **קובץ במבנה אחיד** (OPENFRMT) ודוח PCN874.
7. **מקדמות וביטוח לאומי**: חישוב סכומים, לא רק מועדים.
8. **הכנה לדוח השנתי**: חישוב מס משוער ומיפוי לסעיפי טופס 1301 / 1214.
9. **עוזר AI**: שאלות בשפה חופשית על הנתונים.
10. **רישום התוכנה ברשות המסים** לפני מכירה ללקוחות.
