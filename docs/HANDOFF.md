# מסמך העברה — איפה עצרנו

מסמך זה נכתב כדי שכל שיחה חדשה עם Claude (בענן או במחשב) תמשיך בדיוק מהנקודה שבה עצרנו.
**Claude: קרא את כל המסמך לפני שאתה עושה משהו.**

## עם מי עובדים ואיך

- בעל הפרויקט אינו מתכנת (ידע בסיסי בקוד), סומך על Claude בבניית הקוד, ומקבל החלטות מוצר.
- **כל התקשורת בעברית בלבד** — כולל הודעות ביניים ועדכוני התקדמות. זו בקשה חוזרת ומפורשת.
- **הודעות commit בעברית.**
- לדווח בכנות: מה נבדק, מה לא נבדק (למשל דברים שנבדקו רק על נתונים מדומים), ומה דורש אימות של רואה חשבון.

## מה המוצר

1. **הנהלת חשבונות לעסקים בישראל** (עוסק פטור / מורשה / חברה / שותפות / עמותה): מסמכים ו־PDF, לקוחות וגבייה,
   הוצאות וקבלות (כולל קריאה ב־AI), זיכרון ספקים, ייבוא תנועות בנק והתאמה, דוח מע"מ, דוח שנתי וייצוא, לוח מועדים,
   משתמשים והרשאות, ביקורת עצמית (לוגיקה בלבד, בלי מסך).
2. **מודול ביקורת דוחות למשרדי רואי חשבון** — הכיוון העיקרי כעת. רואת חשבון שהתייעצנו איתה אמרה שזה מה שהכי
   חסר, כי ביקורת דורשת הכי הרבה כוח אדם. המערכת עושה את עבודת הבדיקה; **החתימה על חוות הדעת נשארת אצל רואה חשבון
   מוסמך ובלתי תלוי** (חובה חוקית — אין לזה עקיפה, ויש לומר זאת בכנות).

פירוט מלא של היכולות: `README.md`.

## מודול הביקורת — מה קיים

- תיק ביקורת לכל לקוח מבוקר ושנה, עם הפרדה בין משרדים.
- קליטת **קובץ במבנה אחיד** (BKMVDATA.TXT + INI.TXT) לפי הוראות רשות המסים 1.31, כולל בדיקות שלמות לקובץ.
  המיקומים אומתו מול המפרט הרשמי ומול מימוש עצמאי (Linet, קוד פתוח). אפשר גם כרטסת CSV.
- מאזן בוחן, בדיקת פקודות יומן, חוק בנפורד, מהותיות, מדגם כספי (MUS) עם seed.
- סקירה אנליטית מול שנה קודמת + חודשים חריגים + תיעוד הסברים לכל ממצא.
- התאמת בנק (כולל צ'קים שנפרעו אחרי סוף השנה) ובדיקת סבירות מע"מ עסקאות לפי חודש.

## השלבים הבאים (לפי סדר שסוכם)

1. **ניירות עבודה**: לכל תחום בתיק — מה נבדק, מה נמצא, מי הכין, מי אישר, סטטוס. (ההסברים הקיימים בטבלת
   `audit_notes` הם הבסיס.)
2. **טיוטת מכתב הערות להנהלה** מכל הממצאים בתיק.
3. **השוואה לדיווחי המע"מ בפועל**: קליטת קובץ PCN874 של הלקוח (המפרט ב־gov.il — יש לקרוא אותו, לא לנחש).
4. אחר כך: התאמת בנק "אחד לרבים" (הפקדה אחת לכמה צ'קים), לפי מה שיתגלה בקבצים אמיתיים.

## דברים פתוחים שמחכים לבעל הפרויקט

- **קבצים אמיתיים** (בהסרת פרטים מזהים) — כרטסת / מבנה אחיד מתוכנה נפוצה (חשבשבת, פריוריטי וכו'). עד היום הכול
  נבדק רק על קבצים שנבנו לפי המפרט.
- **שאלה לרואת החשבון**: אילו בדיקות לוקחות למשרד הכי הרבה שעות — כדי לתעדף.
- **מפתחות**: `RESEND_API_KEY` + `EMAIL_FROM` (מיילים), `ANTHROPIC_API_KEY` (קריאת קבלות). ראו `.env.example`.

## סביבת עבודה

- `npm install`, `npm test` (126+ בדיקות), `npm run lint`, `npm run typecheck`, `npm run build`, `npm run dev`.
- מסד נתונים מקומי: PGlite (בלי שרת). שינוי סכמה: `src/db/schema.ts` ואז `npm run db:generate`.
- Next.js 16 — לפני כתיבת קוד, לקרוא את התיעוד שב־`node_modules/next/dist/docs/` (ראו `AGENTS.md`).
- יצירת קבצי מבנה אחיד לבדיקות מכרטסת CSV: `python3 scripts/dev/gen-uniform.py <csv> <outdir> <scale> <year> [skip-accounts]`.
- בדיקות דפדפן נעשו עם Playwright מול `npm start`; כדאי לבדוק כל שינוי גם בדפדפן ולא רק בבדיקות.
- **עיצוב**: מערכת העיצוב ב־`src/app/globals.css` (צבעים, `.card`, `.btn`, `.pills`, `.badge`, `.notice`, `.table-wrap`),
  המעטפת ב־`src/app/(app)/layout.tsx` (פס עליון + תפריט צד עם אייקונים מ־`src/components/icons.tsx`),
  וכותרות/מצבים ריקים/קופסאות מתקפלות ב־`src/components/page-header.tsx`. בעל הפרויקט ביקש ממשק קל, זורם ובהיר —
  לשמור על זה בכל מסך חדש: כותרת + משפט הסבר, טפסים משניים בתוך `Collapsible`, מצב ריק עם הצעד הראשון.
